## ✏️ Задания

1. [x] **Уроки 7–8: OUTER JOIN и NULL.** Реши все упражнения уроков 7 и 8. Перенеси сюда запросы к последним двум упражнениям урока 8 — сотрудники без здания и здания без сотрудников.
   **Критерий сдачи:** упражнения 7–8 решены (SQLBolt показывает ✓); два запроса вставлены сюда.
   **Ответ:**
   ```sql
   -- 1. Сотрудники без здания:
   SELECT Name, Role FROM employees WHERE building IS NULL;

   -- 2. Здания без сотрудников:
   SELECT building_name FROM buildings 
   LEFT JOIN employees ON buildings.building_name = employees.building
   WHERE employees.building IS NULL;
   ```
   *✍️ записано со слов*

2. [x] **Почему INNER JOIN «теряет» пустые здания.** Своими словами, 3–4 предложения: что делает `INNER JOIN` с записью, у которой нет пары; что делает `LEFT JOIN`; почему без `WHERE … IS NULL` ты увидишь все здания, а с ним — только пустые.
   **Критерий сдачи:** объяснено, что происходит с «одинокой» записью в обоих видах JOIN и зачем нужен `IS NULL`.
   **Ответ:** 1. Не добавляет в вывод. 2. Добавляет в вывод. И наоборот с RIGHT - там строка из второй таблицы перекочует даже без пары в первой. 3. Потому что NULL - отсутствие значения в колонке. Вообще следовало сделать проверку по имени, а не зданию, но при соединении у зданий без сотрудников всё равно не будет пары, потому мы можем сделать по любой колонке из employees фильтрацию IS NULL, и результат вернёт только строки зданий без сотрудников.
   *✍️ записано со слов*

3. [x] **Уроки 9–11: выражения и агрегаты.** Реши упражнения уроков 9–11 (если времени мало — хотя бы по два из каждого урока). Сюда вставь один запрос, который тебе показался самым хитрым, и объясни его в одной фразе.
   **Критерий сдачи:** упражнения решены; один запрос с объяснением.
   **Ответ:**
   ```sql
   SELECT SUM(years_employed), role FROM employees
   GROUP BY role
   HAVING role = 'Engineer';
   ```
   *✍️ записано со слов:* Просто последнее из 11 урока. Возвращает суммарное количество отработанных лет инженерами.

## 🟨 Мостик к агентам *(по желанию)*

Когда агент пишет SQL за тебя, классическая тихая ошибка — `INNER JOIN` там, где нужен `LEFT JOIN`: запрос работает, но молча теряет строки без пары, и отчёт «похудел» без единой ошибки в логах. Это хороший пункт для чек-листа ревью кода агента (`0.AIN.07`, неделя 3).
