# 🧰 Инструментарий

> Справочник инструментов, которые пользователь попросил описать: агенты, CLI, библиотеки, сервисы, плагины, программы. **Заполняет Тьютор по запросу** («добавь в инструментарий X», «что за инструмент Y — запиши») — `Тьютор/ВОРКФЛОУ.md`, режим Г → «Инструментарий».
> **Как вести:** одна карточка — один инструмент, внутри разделов — по алфавиту (A–Z, затем А–Я). Если инструмент уже есть — обновлять карточку, а не заводить вторую. Попробовал руками — дописать в «Мой опыт».
> **Не для этого файла:** кино, книги, игры и идеи проектов — `[[Тьютор/Банк идей|Банк идей]]`; новости и релизы — `[[РАДАР]]`.

> [!note]- Формат карточки (раскрыть)
> ```markdown
> ### Название
> - **Что это:** 1–2 предложения простыми словами.
> - **Зачем мне:** какую задачу решает в моей работе или учёбе.
> - **Где в программе:** код занятия, интерес или практика (если есть).
> - **Как начать:** установка или вход, первая команда — коротко.
> - **Цена и лицензия:** бесплатно / платно / open source — какая лицензия.
> - **Похожие:** 1–3 альтернативы и чем отличаются.
> - **Риски:** что даёт доступ к данным, секретам, системе; на что смотреть.
> - **Ссылки:** официальный сайт или документация.
> - **Добавлено:** ДД.ММ.ГГГГ
> - **Мой опыт:** *(заполняется, когда попробовал)*
> ```

## 🤖 Агенты и AI-инструменты

### agent-desktop
- **Что это:** Утилита командной строки (от Vercel Labs), которая даёт агенту управлять обычными программами на компьютере не по скриншотам, а через дерево доступности ОС (accessibility tree: роли, названия, состояния, фокус). Отдаёт дерево в JSON с идентификаторами `ref`: агент нажимает по `ref`, снова читает дерево и проверяет результат.
- **Зачем мне:** Автоматизировать десктопные программы без API (толстые клиенты 1С, бухгалтерские и внутренние корпоративные утилиты). Быстрее, дешевле по токенам и надёжнее, чем computer use по скриншотам. Ограничение: не видит приложения, которые не отдают дерево доступности (самописные контролы, игры, часть Electron-сборок).
- **Где в программе:** `1.AGT.11` (computer use и браузерные агенты: когда оправданы, а когда лучше API).
- **Как начать:** `npm install -g agent-desktop`. Сначала снять неглубокий скелет окна (`--skeleton`), затем раскрывать только нужную ветку (`--root <ref>`), чтобы не сжигать десятки тысяч токенов на полное дерево.
- **Цена и лицензия:** Бесплатно, Open Source (Apache-2.0). Работает на Windows 10 1809+ (UI Automation), macOS 13+ (AX API), Ubuntu 24.04+ (AT-SPI).
- **Похожие:** `agent-browser` (то же для веб-страниц и Electron/Chromium); Playwright (автоматизация веба по DOM без агента); computer use по скриншотам (видит любые пиксели, но медленнее и дороже); классическая RPA (UiPath — та же UI Automation, но сценарии жёстко пишет человек).
- **Риски:** Агент получает руки во всех открытых программах (почта, мессенджеры, банк-клиент, 1С с боевой базой). Тексты в окнах и ячейках — вход для prompt injection. Не запускать с правами администратора; тестировать только под отдельной учёткой и на тестовой базе.
- **Ссылки:** [Документация](https://agent-browser.dev/desktop) · [GitHub: vercel-labs/agent-desktop](https://github.com/vercel-labs/agent-desktop)
- **Добавлено:** 02.11.2026

### GitHub Spec Kit (`spec-kit`)
- **Что это:** Набор инструментов от GitHub Next для ведения разработки через спецификации (Spec-Driven Development) с AI-агентами (Claude Code, Copilot, Gemini CLI).
- **Зачем мне:** Вести разработку фичей по шагам: Конституция (`constitution.md`) → Требования (`spec.md`) → Архитектурный план (`plan.md`) → Задачи (`tasks.md`) → Реализация. Защищает от «вайб-кодинга» и расползания кодовой базы.
- **Где в программе:** `0.AIN.03` (Spec-Driven Development), практика полигона, `0.AIN.08` (контекст проекта).
- **Как начать:** Установка: `uv tool install specify-cli --from git+https://github.com/github/spec-kit.git`. Инициализация: `specify init <project-name> --ai claude`.
- **Цена и лицензия:** Бесплатно, Open Source (MIT).
- **Похожие:** AWS Kiro (агентная IDE со встроенным SDD), Tessl (Spec-as-Source платформа).
- **Риски:** Доступ агента к файлам репозитория при генерации; требует обязательного человеческого ревью каждого артефакта до перехода к коду.
- **Ссылки:** [GitHub: github/spec-kit](https://github.com/github/spec-kit)
- **Добавлено:** 26.10.2026
- **Мой опыт:** Установлен через `uv tool install`. Используется в связке с нашим шаблоном SDD на полигоне «Второй мозг».

### Скилл `/phone` — телефон по SSH
- **Что это:** Личный скилл Claude Code (`~/.claude/skills/phone/SKILL.md`, вне хранилища) для управления телефоном Redmi 13 по SSH и ADB. Читает статус и батарею, вибрирует, озвучивает текст, читает уведомления, работает с буфером обмена, камерой, геолокацией, файлами и экраном.
- **Зачем мне:** Живой стенд к темам «агент с руками в реальной системе»: права, уровни подтверждения, prompt injection из уведомлений и SMS, обратный SSH-туннель. Заодно — личный помощник.
- **Где в программе:** `0.SEC.01` и `0.AGT.07` (права и подтверждения агента), `1.AGT.11` (computer use), `0.NET` (SSH, туннели).
- **Как начать:** `/phone <что сделать>` в Claude Code (связь через `ssh redmi` или `ssh redmi-lan`). Составные части описаны ниже в разделе [[#⌨️ Командная строка и разработка]]: Termux, Termux:API, autossh, ADB.
- **Цена и лицензия:** Бесплатно, собственный скилл (требуется VPS для обратного туннеля).
- **Похожие:** `agent-desktop` (для десктопных ОС); KDE Connect и `scrcpy` (управление телефоном с ПК для человека).
- **Риски и техдолг скилла:**
  - Доступ агента к SMS, звонкам, камере, геолокации и экрану; тексты уведомлений и SMS — потенциальный вектор prompt injection.
  - **Что нужно доработать в скилле:** 1) убрать пин-код открытым текстом из `SKILL.md`; 2) уйти от жёстких координат свайпа `1080x2460`; 3) свести две таблицы уровней доступа в одну; 4) разобраться с фантомным `emulator-5554` в `adb devices`; 5) гасить экран при аварийном завершении.
- **Ссылки:** Локальный файл `C:\Users\Kids-PC\.claude\skills\phone\SKILL.md`
- **Добавлено:** 02.11.2026

## ⌨️ Командная строка и разработка

### ADB (Android Debug Bridge)
- **Что это:** Официальная утилита для отладки Android: командная оболочка, управление приложениями, чтение дерева экрана и симуляция нажатий. В скилле `/phone` работает локально внутри телефона (из Termux на `127.0.0.1:5555`).
- **Зачем мне:** Даёт агенту «глаза и руки» на экране телефона: `uiautomator dump` (XML-дерево элементов экрана с координатами), `screencap` (скриншот), `input tap / swipe / text / keyevent` (клики и ввод).
- **Где в программе:** `1.AGT.11` (computer use), `0.OS` (процессы и права в Android).
- **Как начать:** В Termux — `pkg install android-tools`; включить беспроводную отладку для разработчиков → `adb connect 127.0.0.1:5555`. Пример: `adb -s 127.0.0.1:5555 shell input keyevent 224` (разбудить экран).
- **Цена и лицензия:** Бесплатно, Open Source (Apache-2.0, часть Android SDK Platform-Tools).
- **Похожие:** `scrcpy` (трансляция и управление экраном с ПК); Appium (фреймворк автотестов поверх ADB).
- **Риски:** Почти полный контроль над устройством. Открытый наружу порт `5555` — критическая уязвимость; держать строго на `127.0.0.1` и не вводить через ADB пароли и платёжные данные.
- **Ссылки:** [developer.android.com/tools/adb](https://developer.android.com/tools/adb)
- **Добавлено:** 02.11.2026
- **Мой опыт:** Работает в составе скилла `/phone`.

### autossh
- **Что это:** Обёртка над `ssh`, которая мониторит соединение и автоматически переподнимает его при обрыве. В скилле `/phone` держит постоянный **обратный туннель** с телефона на VPS.
- **Зачем мне:** Достучаться до устройства за NAT и мобильной сетью (4G) без белого IP. Классический инфраструктурный паттерн (который в ИБ также важно знать как механизм reverse-туннелей).
- **Где в программе:** `0.NET` (NAT, SSH, туннелирование), `0.SEC` (обратные каналы связи).
- **Как начать:** В Termux — `pkg install autossh`; запуск: `autossh -M 0 -N -R 18022:127.0.0.1:8022 <сервер>`.
- **Цена и лицензия:** Бесплатно, Open Source (BSD-подобная лицензия).
- **Похожие:** Обычный `ssh -R` (не переподключается при разрыве); Tailscale / WireGuard (полноценная overlay VPN-сеть вместо проброса одного порта); ngrok (облачный туннель).
- **Риски:** VPS становится точкой входа на телефон. SSH-ключ телефона на VPS должен быть ограничен только пробросом порта (без shell-доступа), а порт на VPS — слушать только `127.0.0.1`.
- **Ссылки:** [harding.motd.ca/autossh](https://www.harding.motd.ca/autossh/)
- **Добавлено:** 02.11.2026
- **Мой опыт:** Работает в составе скилла `/phone`.

### Termux
- **Что это:** Терминал и изолированное Linux-окружение на Android без root-прав со своим пакетным менеджером (`pkg`), Python, Git и OpenSSH.
- **Зачем мне:** Превращает Android-смартфон в карманный Linux-сервер (`sshd` на порту 8022, `autossh`, локальный ADB).
- **Где в программе:** `0.OS` (процессы, права, песочницы приложений), `0.NET` (SSH).
- **Как начать:** Устанавливать с F-Droid или GitHub Releases (версия в Google Play устарела и несовместима), затем `pkg install openssh` и запуск `sshd`.
- **Цена и лицензия:** Бесплатно, Open Source (GPLv3).
- **Похожие:** UserLAnd (полный дистрибутив Linux поверх Android); `adb shell` (урезанная системная оболочка без пакетного менеджера).
- **Риски:** Агрессивный энергосберегающий режим оболочки (HyperOS/MIUI) может убивать фоновый процесс Termux. В `sshd_config` обязательно отключить вход по паролю (`PasswordAuthentication no`), оставив только ключи.
- **Ссылки:** [termux.dev](https://termux.dev) · [GitHub: termux/termux-app](https://github.com/termux/termux-app)
- **Добавлено:** 02.11.2026
- **Мой опыт:** Работает в составе скилла `/phone`.

### Termux:API
- **Что это:** Аддон к Termux (отдельное Android-приложение + пакет `termux-api`), открывающий доступ к железу и функциям телефона из командной строки с ответами в JSON (`termux-battery-status`, `termux-vibrate`, `termux-tts-speak`, `termux-notification-list`, `termux-location`, `termux-camera-photo`, `termux-sms-list` и др.).
- **Зачем мне:** Даёт агенту «органы чувств» смартфона через простые CLI-вызовы.
- **Где в программе:** `0.SEC.01`, `0.AGT.07` (наглядная модель гранулярных разрешений для инструментов агента).
- **Как начать:** Установить APK `Termux:API` из того же источника (F-Droid/GitHub), в консоли выполнить `pkg install termux-api` и выдать нужные разрешения в настройках Android.
- **Цена и лицензия:** Бесплатно, Open Source (GPLv3).
- **Похожие:** Tasker (визуальная автоматизация на Android); прямые вызовы через ADB.
- **Риски:** Все разрешения, выданные приложению Termux:API, автоматически доступны любому скрипту и агенту внутри Termux. Входящие SMS и пуш-уведомления — недоверенный внешний ввод (риск prompt injection).
- **Ссылки:** [wiki.termux.com/wiki/Termux:API](https://wiki.termux.com/wiki/Termux:API)
- **Добавлено:** 02.11.2026
- **Мой опыт:** Работает в составе скилла `/phone`.

## 🧪 Тестирование и качество

### Hypothesis
- **Что это:** Библиотека Python для property-based тестирования (тестов-свойств). Вместо ручного перебора примеров ты задаёшь стратегию генерации входных данных и инвариант (свойство, которое должно выполняться всегда). Библиотека сама генерирует сотни каверзных входов, а при падении автоматически сжимает (shrink) вход до минимального воспроизводимого примера (`Failing test case`).
- **Зачем мне:** Находить пограничные баги (пустые строки, спецсимволы, переполнения, кривые пути), о которых не подумал ни я, ни агент. Идеальный предохранитель против агента, который подогнал код под 3 захардкоженных `assert`.
- **Где в программе:** `0.AIN.04` (Сессия 9, тесты как спецификация), тесты безопасности путей в полигоне «Второй мозг».
- **Как начать:** `pip install hypothesis` (или `uv add --dev hypothesis`), запуск штатно через `pytest`:
  ```python
  from hypothesis import given, strategies as st

  @given(st.lists(st.integers()))
  def test_sorted_len(xs):
      assert len(sorted(xs)) == len(xs)
  ```
- **Цена и лицензия:** Бесплатно, Open Source (MPL-2.0, Python 3.11+).
- **Похожие:** `pytest.mark.parametrize` (ручной список кейсов); Schemathesis (генерация тестов для HTTP API по OpenAPI-схеме на базе Hypothesis); `mutmut` (мутационное тестирование — вносит баги в код и проверяет, упадут ли тесты, будет в `0.AIN.09`).
- **Риски:** Работает локально. Если тестируемая функция ходит в сеть, БД или на диск, Hypothesis дёрнет её 100+ раз подряд (используй моки или `tmp_path`). Локальный кэш `.hypothesis/` нужно добавлять в `.gitignore`.
- **Ссылки:** [Документация Hypothesis](https://hypothesis.readthedocs.io/en/latest/quickstart.html) · [PyPI](https://pypi.org/project/hypothesis/)
- **Добавлено:** 02.11.2026

### pre-commit
- **Что это:** Фреймворк для управления git-хуками (`pre-commit hook`). Автоматически запускает настроенные проверки (линтеры, форматтеры, сканеры безопасности, поиск забытых секретов) в момент выполнения `git commit`, и если проверка падает — блокирует создание коммита.
- **Зачем мне:** Защита от человеческой забывчивости и огрехов агентов. Не даёт закоммитить код с битым синтаксисом, плохим стилем, забытыми API-ключами или падающими базовыми проверками.
- **Где в программе:** Практика полигона «Второй мозг», `1.DEV.03` (автоматизация проверок и качество репозитория).
- **Как начать:** `pip install pre-commit` (или `uv tool install pre-commit`). Создать конфиг `.pre-commit-config.yaml` в корне репозитория и активировать хуки: `pre-commit install`. Ручной прогон по всем файлам проекта: `pre-commit run --all-files`.
- **Цена и лицензия:** Бесплатно, Open Source (MIT).
- **Похожие:** Lefthook (быстрый менеджер хуков на Go); husky (популярен в JS/TS экосистеме); чистые скрипты в `.git/hooks/` (ручная поддержка без изоляции версий).
- **Риски:** Если хуки настроены тяжело (например, долгие интеграционные тесты), коммиты начинают тормозить, и разработчик начинает писать `git commit --no-verify`. В pre-commit хуки ставятся в изолированные виртуальные окружения в `~/.cache/pre-commit`.
- **Ссылки:** [pre-commit.com](https://pre-commit.com/) · [GitHub: pre-commit/pre-commit](https://github.com/pre-commit/pre-commit)
- **Добавлено:** 05.11.2026

### Ruff
- **Что это:** Экстремально быстрый линтер и форматтер кода для Python, написанный на Rust компанией Astral (создатели `uv`). Заменяет собой целый стек старых утилит: Flake8 (с десятками плагинов), Black, isort, pydocstyle, pyupgrade и autoflake, работая в 10–100 раз быстрее.
- **Зачем мне:** Мгновенно проверять и форматировать код (свой и написанный агентом) прямо при сохранении или перед коммитом. Находит неиспользуемые импорты, синтаксические ошибки, антипаттерны, неэффективные конструкции и даже базовые проблемы безопасности (включая правила из Bandit через флаг `flake8-bandit` / `S`).
- **Где в программе:** Практика полигона «Второй мозг», `0.AIN.06`–`0.AIN.07` (чтение и ревью кода), `1.DEV.03` (настройка CI-пайплайнов).
- **Как начать:** `uv add --dev ruff` (или `pip install ruff`). Проверка: `ruff check .`, автоисправление: `ruff check --fix .`, форматирование: `ruff format .`. Правила безопасности `S` по умолчанию **выключены** — включить в `pyproject.toml`: `[tool.ruff.lint] extend-select = ["S"]`, а в тестах выключить `S101` (`assert` нужен pytest): `[tool.ruff.lint.per-file-ignores] "tests/**" = ["S101"]`. В наборе `S` 71 правило, 56 стабильных *(сверено по docs.astral.sh 13.11.2026)*. Самые полезные для кода от агентов: `S101` assert вместо проверки, `S102`/`S307` exec и eval, `S105–S107` пароль в коде, `S108` жёсткий путь во временную папку, `S110`/`S112` молча проглоченное исключение, `S113` запрос без тайм-аута, `S301` pickle, `S324` слабый хеш, `S501` запрос без проверки сертификата, `S506` небезопасный `yaml.load`, `S602`–`S607` запуск процессов и оболочки, `S608` SQL, собранный из строк.
- **Цена и лицензия:** Бесплатно, Open Source (MIT).
- **Похожие:** Flake8 (медленнее, написан на Python); Black (только форматтер); Pylint (глубже анализирует типы и наследование, но значительно медленнее).
- **Риски:** Автоисправление (`--fix`) в редких случаях может изменить логику нетривиального кода; опасные исправления (`--unsafe-fixes`) запускать только осознанно и с чистым `git status`.
- **Ссылки:** [docs.astral.sh/ruff](https://docs.astral.sh/ruff/) · [GitHub: astral-sh/ruff](https://github.com/astral-sh/ruff)
- **Добавлено:** 05.11.2026

### Bandit
- **Что это:** Специализированный SAST-линтер безопасности от сообщества PyCQA / OpenStack для поиска типовых уязвимостей в коде на Python. Разбирает код в абстрактное синтаксическое дерево (AST) и прогоняет его по набору встроенных плагинов-проверок.
- **Зачем мне:** Ловить детские и опасные ошибки безопасности в коде Python (своём и от агентов): вызовы `eval()` и `exec()`, `shell=True` в `subprocess`, генерацию слабых псевдослучайных чисел (`random` вместо `secrets`), небезопасную десериализацию (`pickle.loads`), отключение проверки SSL-сертификатов (`verify=False`) и захардкоженные пароли/токены.
- **Где в программе:** `0.SEC.01`–`0.SEC.03`, ревью кода от агента (`0.AIN.07`), security-пайплайн CI полигона.
- **Как начать:** `pip install bandit` (или `uv add --dev bandit`). Запуск сканирования папки: `bandit -r src/` (или с фильтром по уровню критичности `-ll` / `-ii`).
- **Цена и лицензия:** Бесплатно, Open Source (Apache-2.0).
- **Похожие:** Semgrep (более гибкий, поддерживает кастомные правила и много языков); Ruff с плагином `flake8-bandit` (правила `S` — быстрее, но покрывает не все сложные сценарии Bandit).
- **Риски:** Ложные срабатывания (false positives) на утилитарных скриптах и тестах (например, на безобидный `assert` или `random`). Настраивается файлом конфигурации `.bandit` или комментариями `# nosec`.
- **Ссылки:** [bandit.readthedocs.io](https://bandit.readthedocs.io/en/latest/) · [GitHub: PyCQA/bandit](https://github.com/PyCQA/bandit)
- **Добавлено:** 05.11.2026

### DFD (Data Flow Diagram)
- **Что это:** Метод визуализации архитектуры через потоки данных. Схема состоит из 5 элементов: внешние сущности (кто снаружи), процессы (код/агент), хранилища (файлы/БД), потоки данных (стрелки с подписью, что течёт) и **границы доверия** (пунктир, где меняется уровень контроля и прав).
- **Зачем мне:** Фундамент моделирования угроз. Без DFD непонятно, к чему прикладывать STRIDE. Главные уязвимости почти всегда сидят там, где поток данных пересекает границу доверия.
- **Где в программе:** `0.SEC.01` (Сессия 10), design doc полигона (нед. 3), `0.AIS.03` и практика нед. 13, лекция [[Материалы/Тьютор/Неделя 03 (02.11–08.11)/DFD и STRIDE — моделирование угроз от потоков данных к защите|DFD и STRIDE]].
- **Как начать:** Рисовать через Mermaid прямо в Obsidian (`flowchart LR` + `subgraph` для границ доверия) либо в специализированных редакторах ниже (Threat Dragon, Microsoft TMT).
- **Цена и лицензия:** Бесплатно (методология).
- **Похожие:** Диаграмма развёртывания (показывает инфраструктуру и серверы, а не движение данных); нотация C4 (масштабируемые уровни архитектуры, но без акцента на границах доверия).
- **Риски:** Диаграмма легко превращается в «бумажную фантазию», если не сверять её с реальными конфигами, правами ОС и сетевыми портами.
- **Ссылки:** [OWASP Threat Modeling Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Threat_Modeling_Cheat_Sheet.html)
- **Добавлено:** 03.11.2026

### OWASP pytm
- **Что это:** Python-библиотека для описания модели угроз в виде кода (Threat Modeling as Code). Описываешь архитектуру классами (`Actor`, `Server`, `Datastore`, `Dataflow`, `Boundary`), а скрипт сам генерирует DFD-схему, sequence-диаграмму и Markdown/HTML-отчёт с угрозами (включая коды для LLM, например `LLM01`).
- **Зачем мне:** Модель угроз живёт в Git-репозитории полигона рядом с кодом на родном Python: изменил архитектуру → перезапустил скрипт → обновил схему и отчёт.

- **Как начать:** Нужны Python 3.11+ и Graphviz (в WSL2 или Docker):

- **Цена и лицензия:** Бесплатно, Open Source (MIT, активная разработка).
- **Похожие:** Threagile (та же концепция «модель как код», но декларативно на YAML вместо Python); [[#OWASP Threat Dragon]] (визуальный редактор).
- **Риски:** Автоматически сгенерированный список угроз — это базовая заготовка по шаблонам, она не заменяет вдумчивый анализ логики приложения.

### SAST (Static Application Security Testing)
- **Что это:** Класс инструментов и методология автоматического анализа исходного кода (белый ящик, white-box) на наличие уязвимостей, захардкоженных секретов и нарушений стандартов безопасности без компиляции и запуска самой программы.
- **Зачем мне:** Ловить архитектурные и кодовые дыры безопасности на этапе написания кода и в CI/CD (shift-left security). В связке с AI-агентами — автоматический фильтр первого уровня, отсекающий очевидный небезопасный код от LLM.
- **Где в программе:** `0.SEC.01`–`0.SEC.03`, `0.AIN.07` (ревью кода), `1.DEV.03` (security gates в CI/CD), `1.AIS.03` (безопасность кода агентов).
- **Как начать:** Выбрать инструмент под язык и стек (для Python — Bandit, для мультиязычных проектов — Semgrep), настроить базовые правила и встроить в pre-commit или CI.
- **Цена и лицензия:** Методология. Есть как бесплатные open-source сканеры (Bandit, Semgrep OSS, Trivy), так и enterprise-платформы (SonarQube, Checkmarx, Snyk, GitHub CodeQL).
- **Похожие:** DAST (динамический анализ — сканирует работающее приложение снаружи как атакующий); IAST (интерактивный анализ внутри процесса); SCA (Software Composition Analysis — сканирует уязвимости в зависимостях/библиотеках).
- **Риски:** Главная проблема SAST — ложные срабатывания (false positives), которые раздражают разработчиков, и ложное чувство безопасности (false negatives): SAST не видит логических ошибок бизнес-процессов и уязвимостей рантайма.
- **Ссылки:** [OWASP Source Code Analysis Tools](https://owasp.org/www-community/Source_Code_Analysis_Tools)
- **Добавлено:** 05.11.2026

### Semgrep
- **Что это:** Быстрый полиглотный инструмент статического анализа кода (SAST) и поиска секретов, правила для которого пишутся на понятном синтаксисе самого целевого языка (а не на сложных внутренних DSL).
- **Зачем мне:** Находить уязвимости (OWASP Top 10), утечки секретов и писать **собственные правила безопасности** для своего проекта за 5 минут. Например, можно одним правилом запретить вызов `open()` без явного указания кодировки `encoding="utf-8"` или запретить использование функции обхода путей.
- **Где в программе:** `0.SEC.01`–`0.SEC.03`, безопасность полигона «Второй мозг», `1.AIS.03`.
- **Как начать:** `pip install semgrep` (или запуск через Docker/CLI). Быстрый аудит репозитория по стандартным правилам: `semgrep scan --config auto`.
- **Цена и лицензия:** движок Semgrep Community Edition (бывший Semgrep OSS) — бесплатно, LGPL-2.1. Правила реестра с декабря 2024 — под Semgrep Rules License: можно для своего кода, нельзя в конкурирующем продукте или SaaS. Межфункциональный taint-анализ ушёл в платную платформу. Ответ сообщества — форк **Opengrep** (январь 2025, LGPL-2.1, полностью открытый) *(сверено 13.11.2026: [The New Stack](https://thenewstack.io/opengrep-launches-as-free-fork-after-semgrep-license-shift/), [InfoQ](https://www.infoq.com/news/2025/02/semgrep-forked-opengrep))*.
- **Как в полигоне:** `semgrep scan --config p/python --config .semgrep/ --metrics off` — набор правил Python плюс свои правила проекта (`AGENTS.md` полигона, §2). `--config auto` по документации отправляет в реестр URL проекта, поэтому не используем.
- **Похожие:** CodeQL от GitHub (очень мощный семантический анализ через SQL-подобные запросы, но сложнее в написании правил); Bandit (только Python); SonarQube.
- **Риски:** При использовании сторонних наборов правил (`--config p/default`) часть сетевых сканеров может слать телеметрию или метаданные в облако вендора. Для полной изоляции запускать с локальными наборами правил без интернета.
- **Ссылки:** [semgrep.dev](https://semgrep.dev/) · [GitHub: semgrep/semgrep](https://github.com/semgrep/semgrep)
- **Добавлено:** 05.11.2026

### STRIDE (метод)

| Буква | Угроза | Какое свойство ломает |
|---|---|---|
| **S** — Spoofing | Подмена личности | Подлинность (Аутентификация) |
| **T** — Tampering | Подмена данных | Целостность |
| **R** — Repudiation | Отказ от авторства действий | Неотказуемость (Логи и аудит) |
| **I** — Information Disclosure | Утечка информации | Конфиденциальность |
| **D** — Denial of Service | Отказ в обслуживании | Доступность |
| **E** — Elevation of Privilege | Повышение привилегий | Авторизация |

- **Что это:** Классический чек-лист из 6 категорий угроз (разработан в Microsoft), который прикладывают к каждому узлу и потоку данных на DFD-схеме.
- **Зачем мне:** Систематизирует поиск дыр, чтобы не полагаться на «что случайно пришло в голову». Для агентных систем применяется в связке с OWASP LLM Top 10 (prompt injection и избыточные права инструментов обычно проецируются на **T**, **I** и **E**).
- **Где в программе:** `0.SEC.01`, `0.AIS.02–03`, практика нед. 13, `Шаблоны/Модель угроз.md`, карточки `Фаза0/SEC`.
- **Как начать:** Взять один поток данных, пересекающий границу доверия, и последовательно проверить его по всем 6 буквам таблицы.
- **Цена и лицензия:** Бесплатно (методология).
- **Похожие:** LINDDUN (фокус на приватности и ПДн); PASTA (моделирование от бизнес-рисков); MAESTRO (угрозы мультиагентных AI-систем); DREAD (шкала для численной оценки критичности уже найденных угроз).
- **Риски:** Это проверочный список категорий, а не автоматический сканер уязвимостей.
- **Ссылки:** [Microsoft Learn — STRIDE](https://learn.microsoft.com/azure/security/develop/threat-modeling-tool-threats)
- **Добавлено:** 03.11.2026

- **Риски:** Сторонний скилл — это чужой код и промпты с правами твоего агента. **Обязательно вычитать `SKILL.md` и все Python/Bash-скрипты перед запуском.** Активные фазы (генерация эксплойтов и запуск сканеров ZAP/Nuclei/SQLMap) запускать исключительно на собственном локальном полигоне.

## 📦 Песочницы и изоляция (Windows)

> [!info] Контекст твоего ПК
> **ОС:** Windows 11 **Home** Single Language. Установлены **WSL2** (`Ubuntu`, `docker-desktop`) и **Docker Desktop**. Встроенные *Hyper-V* и *Windows Sandbox* в редакции Home отсутствуют (доступны только в Pro/Enterprise).

| Практическая задача | Чем решать на твоём ПК |
|---|---|
| Спрятать от агента-кодера `.env`, `~/.ssh` и личные папки на диске | [[#Dev Container для Claude Code\|Dev Container]] или [[#WSL2 как песочница\|WSL2]] + [[#Claude Code — встроенная песочница (`/sandbox`)\|Claude /sandbox]]; либо [[#Отдельная учётка Windows + права на файлы (`icacls`)\|отдельная учётка + icacls]] |
| Быстро запустить подозрительный `.exe` или незнакомую утилиту | [[#Sandboxie-Plus]] (быстро, общее ядро) или [[#VirtualBox]] (надёжно, отдельное ядро) |
| Чистая Windows «на один раз» со сбросом | [[#VirtualBox]] со снимком (snapshot) — полноценная замена недоступному на Home *Windows Sandbox* |
| Пустить агента работать автономно без подтверждений в микро-ВМ | [[#Docker Sandboxes (`sbx`)\|Docker Sandboxes]] |

### Claude Code — встроенная песочница (`/sandbox`)
- **Что это:** Штатный режим изоляции в Claude Code, при котором shell-команды и их дочерние процессы ограничиваются на уровне ОС: запись разрешена только в текущую рабочую папку и `/tmp`, а выход в сеть идёт через прокси по белому списку доменов.
- **Зачем мне:** Не дать агенту-кодеру случайно или из-за prompt injection испортить файлы вне проекта или слить данные в сеть.
- **Где в программе:** `0.OS.08` (механизмы изоляции), `1.AGT.12` (coding-агент в песочнице), `1.AIS.04`.
- **Как начать:** Нативно в Windows не работает — **только внутри WSL2** (или на Linux/macOS). В Ubuntu (WSL2): `sudo apt-get install bubblewrap socat`, затем в Claude Code выполнить `/sandbox` (или прописать `"sandbox": {"enabled": true}` в `~/.claude/settings.json`).
- **Цена и лицензия:** Бесплатно (встроено в Claude Code, движок `@anthropic-ai/sandbox-runtime` — Open Source).
- **Похожие:** [[#Dev Container для Claude Code]] (изолирует всё окружение, а не только shell-вызовы); [[#Docker Sandboxes (`sbx`)]].
- **Риски:** По умолчанию песочница ограничивает **запись**, но оставляет открытым **чтение** почти всего диска (включая `~/.ssh` и примонтированный в WSL2 диск `/mnt/c`), пока ты явно не закроешь чтение в конфиге. Встроенные файловые тулы Claude и MCP-серверы работают в обход shell-песочницы.
- **Ссылки:** [Документация Claude Code — Sandboxing](https://code.claude.com/docs/en/sandboxing)
- **Добавлено:** 03.11.2026

### Dev Container для Claude Code
- **Что это:** Docker-контейнер по стандарту Dev Containers, внутри которого запускается сам Claude Code. В контейнер монтируется только папка текущего проекта, а вся остальная файловая система хоста для агента физически не существует.
- **Зачем мне:** Самый надёжный и простой способ на Windows Home изолировать агента так, чтобы он видел исключительно репозиторий полигона и не имел доступа к `C:\Users` и хранилищу Obsidian.
- **Где в программе:** `0.OS.08`, `1.AGT.12`, `1.AIS.04`, практика полигона.
- **Как начать:** VS Code + расширение *Dev Containers* + Docker Desktop. Положить в проект `.devcontainer/devcontainer.json` (у Anthropic есть готовый шаблон со встроенным iptables-файрволом на исходящую сеть) → `Dev Containers: Rebuild and Reopen in Container` → запускать `claude` в терминале контейнера.
- **Цена и лицензия:** Бесплатно.
- **Похожие:** [[#Claude Code — встроенная песочница (`/sandbox`)]] в WSL2; [[#Docker Sandboxes (`sbx`)]].
- **Риски:** Всё, что лежит **внутри** примонтированной папки проекта (включая `.env`) и учётные данные самого Claude Code в контейнере (`~/.claude`), остаётся доступным агенту. Никогда не пробрасывать внутрь контейнера `~/.ssh` и `docker.sock`.
- **Ссылки:** [Документация Claude Code — Dev Containers](https://code.claude.com/docs/en/devcontainer) · [Референсный .devcontainer от Anthropic](https://github.com/anthropics/claude-code/tree/main/.devcontainer)
- **Добавлено:** 03.11.2026

### Docker Desktop
- **Что это:** Платформа контейнеризации. На Windows Home работает поверх служебной ВМ в WSL2 (`docker-desktop`) и запускает изолированные Linux-контейнеры (изоляция процессов через Linux namespaces и лимиты ресурсов через cgroups на общем ядре Linux-ВМ).
- **Зачем мне:** Базовый фундамент для запуска Dev Containers, локальных сервисов (БД, векторных хранилищ, STRIDE GPT) и упаковки своих проектов.
- **Где в программе:** `0.OS.08` (устройство контейнеров), `1.NET.06` (сети контейнеров), `1.AIS.04`.
- **Как начать:** Быстрый одноразовый контейнер с Python только над текущей папкой и без интернета:
  `docker run --rm -it --network none -v ${PWD}:/work -w /work python:3.12 bash`
- **Цена и лицензия:** Бесплатно для личного использования и малого бизнеса.
- **Похожие:** Podman Desktop (без фонового root-демона), Rancher Desktop.
- **Риски:** Проброс `/var/run/docker.sock` или флаг `--privileged` полностью разрушают изоляцию и дают контейнеру root-доступ к хосту. Контейнеры делят общее ядро Linux-ВМ, поэтому для запуска откровенных эксплойтов лучше использовать полноценную ВМ (VirtualBox).
- **Ссылки:** [Docker Desktop Docs](https://docs.docker.com/desktop/)
- **Добавлено:** 03.11.2026
- **Мой опыт:** Установлен и работает на ПК (через бэкенд WSL2).

### Docker Sandboxes (`sbx`)
- **Что это:** Специализированный CLI-инструмент от Docker для запуска coding-агентов (включая Claude Code) не в обычном контейнере, а в отдельной легковесной **микро-ВМ** со своим собственным ядром ОС.
- **Зачем мне:** Максимальный уровень изоляции для автономной работы агента без подтверждений (сильнее обычного Docker-контейнера за счёт отдельного ядра).
- **Где в программе:** `1.AIS.04` (микро-ВМ, gVisor / Firecracker), `1.AGT.12`.
- **Как начать:** `winget install -h Docker.sbx` → авторизоваться в Docker → в папке проекта выполнить `sbx run --name my-sandbox claude`.
- **Цена и лицензия:** Бесплатно (требуется учётная запись Docker).
- **Похожие:** [[#Dev Container для Claude Code]] (обычный контейнер); [[#VirtualBox]] (тяжёлая классическая ВМ).
- **Риски:** Опирается на системную платформу виртуализации Windows (Virtual Machine Platform) — перед боевым применением проверить совместимость со своей сборкой Windows 11 Home. Токены и ключи, переданные внутрь микро-ВМ, всё так же доступны агенту.
- **Ссылки:** [Docker Sandboxes Docs](https://docs.docker.com/ai/sandboxes/get-started/)
- **Добавлено:** 03.11.2026

### Sandboxie-Plus
- **Что это:** Легковесная песочница для нативных Windows-программ (`.exe`). Перехватывает обращения процесса через системный драйвер и перенаправляет все попытки записи на диск и в реестр в изолированную папку-«коробку».
- **Зачем мне:** Замена недоступному на Windows Home *Windows Sandbox*, когда нужно за 2 секунды безопасно открыть незнакомую Windows-утилиту или файл и после закрытия стереть все следы в один клик.
- **Где в программе:** `0.OS.08`, поток интересов `CTF`.
- **Как начать:** Скачать установщик из GitHub Releases → правый клик по `.exe` → *Run Sandboxed*. В настройках коробки для недоверенных программ сразу отключать сеть и закрывать чтение личных папок.
- **Цена и лицензия:** Бесплатно, Open Source (GPL-3.0).
- **Похожие:** [[#VirtualBox]] (отдельное ядро ОС, намного надёжнее, но дольше запускать); *Windows Sandbox* (встроенная одноразовая ВМ, доступна только на Windows Pro/Enterprise).
- **Риски:** Процесс в Sandboxie работает на **том же ядре Windows**, что и хост (уязвимость ядра или драйвера позволит пробить песочницу). По умолчанию изолирует запись, но **разрешает чтение** пользовательских файлов — для защиты секретов нужно явно настраивать закрытые пути.
- **Ссылки:** [sandboxie-plus.com](https://sandboxie-plus.com/) · [GitHub: sandboxie-plus/Sandboxie](https://github.com/sandboxie-plus/Sandboxie)
- **Добавлено:** 03.11.2026

### VirtualBox
- **Что это:** Классический гипервизор 2-го типа от Oracle для создания полноценных виртуальных машин (Windows, Linux) с отдельным ядром, виртуальным железом и системой снимков состояния (snapshots).
- **Зачем мне:** Самая бронебойная изоляция на Windows Home: стенд для разбора вредоносов в CTF, тестирование подозрительного софта и эксперименты с computer use агентами на «чистой» гостевой ОС.
- **Где в программе:** `0.OS.08`, `1.AIS.04`, интересы `CTF` и `LOW`.
- **Как начать:** Установить с официального сайта → накатить образ ОС → сразу сделать базовый снимок (Snapshot «Clean State»), чтобы откатывать систему в исходное состояние за 5 секунд.
- **Цена и лицензия:** Бесплатно, Open Source (GPL-3.0; плагин Extension Pack — бесплатен для личного и учебного использования по лицензии PUEL).
- **Похожие:** VMware Workstation Pro, Hyper-V (только на Windows Pro).
- **Риски:** Для полной изоляции обязательно отключать общие папки (Shared Folders), общий буфер обмена и Drag-and-Drop, а сетевой адаптер переводить в режим NAT или Host-only (либо отключать совсем).
- **Ссылки:** [virtualbox.org](https://www.virtualbox.org/wiki/Downloads)
- **Добавлено:** 03.11.2026

### WSL2 как песочница
- **Что это:** Подсистема Windows для Linux — полноценное ядро Linux внутри легковесной служебной ВМ.
- **Зачем мне:** Удобная Linux-среда для разработки полигона и единственный способ запустить штатную песочницу [[#Claude Code — встроенная песочница (`/sandbox`)]] на Windows.
- **Где в программе:** `0.OS.08`, практика полигона.
- **Как начать:** Уже установлена (`wsl -d Ubuntu`). Чтобы превратить WSL2 из «прозрачной среды» в изолированную, в файле `/etc/wsl.conf` отключают автомонтирование дисков Windows и запуск `.exe`:
  ```ini
  [automount]
  enabled = false
  [interop]
  enabled = false
  ```
  *(после правки перезапустить через `wsl --shutdown` в PowerShell).*
- **Цена и лицензия:** Бесплатно (встроено в Windows).
- **Похожие:** [[#Docker Desktop]] (работает поверх той же ВМ WSL2); [[#VirtualBox]] (полностью независимая ВМ).
- **Риски:** **В настройках по умолчанию WSL2 НЕ является песочницей:** из Ubuntu свободно читается и пишется весь диск `C:` через `/mnt/c/Users/...`, включая хранилище Obsidian и `.env`.
- **Ссылки:** [Документация Microsoft — WSL](https://learn.microsoft.com/en-us/windows/wsl/wsl-config)
- **Добавлено:** 03.11.2026
- **Мой опыт:** Установлен и используется дистрибутив `Ubuntu`.

### Отдельная учётка Windows + права на файлы (`icacls`)
- **Что это:** Штатный механизм разграничения доступа ОС Windows (ACL — списки контроля доступа): агент запускается от имени отдельного локального пользователя без прав администратора, которому на уровне файловой системы NTFS запрещено чтение секретов (`.env`, `~/.ssh`, личных папок).
- **Зачем мне:** Базовая защита секретов без контейнеров и виртуалок (решение из Сессии 10: агент-кодер физически не может прочитать `.env`, даже если его попросят через prompt injection).
- **Где в программе:** `0.SEC.01` (защита ключей), `0.OS.08`.
- **Как начать:**
  1. Создать локального пользователя Windows без прав администратора (например, `agent_runner`).
  2. Закрыть `.env` от всех, кроме своей основной учётки:
     `icacls .env /inheritance:r /grant:r "${env:USERNAME}:F"`
  3. Запускать агента от имени ограниченной учётки (`runas /user:agent_runner ...`).
- **Цена и лицензия:** Бесплатно (встроено в ОС Windows).
- **Похожие:** [[#Dev Container для Claude Code]] (изоляция через монтирование папки); `chmod 600` + отдельный user в Linux.
- **Риски:** Сам рабочий процесс сервера полигона, которому ключ нужен для работы, всё равно должен иметь к нему доступ (а значит, и подключённые внутрь него Python-библиотеки). Поэтому права ОС всегда дополняются лимитом бюджета (spending limit) в кабинете LLM-провайдера.
- **Ссылки:** [Microsoft Learn — icacls](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/icacls)
- **Добавлено:** 03.11.2026
