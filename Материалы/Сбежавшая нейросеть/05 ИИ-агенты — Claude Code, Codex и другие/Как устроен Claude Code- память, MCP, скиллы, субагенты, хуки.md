# Как устроен Claude Code: память, MCP, скиллы, субагенты, хуки

[![](https://images.boosty.to/image/ea8ba0ff-7965-469e-9e5a-94fd3828aa3d?change_time=1776445953&mw=575)](https://boosty.to/escaped_ai/posts/ac0fc839-00b9-47b1-a3e4-3182a4f1da1f/media/ea8ba0ff-7965-469e-9e5a-94fd3828aa3d?from=blog_post)

Claude Code выглядит как командная строка из 90-х: черный экран, мигающий курсор – и все. А внутри – шесть слоев, которые превращают его в конструктор, где программирование это только один из сценариев.

Ранее я [**рассказал**](https://boosty.to/escaped_ai/posts/11aaeaa6-baf7-428d-8bbd-76dad4fd56ca) про философию ИИ-агентов Claude Code и Codex: в отличие от чат-ботов, это полноценные партнеры в самой разной работе: от написания кода до разбора аналитики и создания презентаций. Сегодня лезем под капот Claude Code: из каких "слоев" он состоит, как устроена память, какие команды надо знать, зачем нужны скиллы, MCP и субагенты.

Из комментариев к предыдущему тексту я вижу, что многие работают с Codex. Сигнал принят – по "Кодексу" обязательно будет отдельная ветка текстов, но немного позже. Только что OpenAI кардинально обновила десктопный Codex, трансформировав его в универсального ассистента для всего: от диалогов до сложных проектов, требующих компьютерного зрения и использования браузера. Звучит очень круто, так что буду разбираться – и как только накоплю достаточно знаний, приступлю к текстам. А пока совет: принципы работы Claude Code и Codex очень близки, поэтому любой мой текст можно скормить "Кодексу" и попросить дать комментарии, как описанные мной вещи работают в нем.

Разберем все шесть слоев по порядку: от памяти и подключения внешних сервисов до скиллов, субагентов и хуков. С живыми примерами из моей работы – без пересказа документации.

## Запуск и slash-команды

Итак, вы установили Claude Code, запустили терминал, набрали в нем Claude. В таком случае агент обычно запускается из вашей пользовательской папки – у меня это C:\\Users\\Andrew – и сразу спрашивает разрешения работать в ней. Жмите Yes, I trust this folder.

Это и есть главная особенность Claude Code: он ставится на ваш компьютер и может хозяйничать в той папке, где вы ему разрешите. После чат-бота это немного сбивает с толку, поэтому я советую выделить Claude Code рабочий каталог, внутри которого он будет сортировать проекты по подкаталогам. Эти проекты вы можете воспринимать как "чаты": здесь ассистент редактора, здесь работаем с аналитикой, а здесь Claude Code парсит нужные тексты и данные, которые затем используются сразу несколькими проектами (другими папками).

Работу с каталогами и папками внутри Claude может взять на себя: при старте нового проекта я пишу "разрабатываем агента для поиска новых скиллов, создай для него папку", а если нужно работать в уже сделанном, то набираю что-то вроде "стартуй ассистента редактора" – модель разбирается и переходит в нужную папку. Также вы можете в командной строке перейти в нужную папку командой cd – наберите "cd ", а затем путь. Пример: cd C:\\Users\\Andrew\\Projects\\my-agent на Windows или cd ~/Projects/my-agent на Mac. И стартовать агента уже оттуда – тогда без разрешения у него не будет доступа к другим папкам. Лайфхак: путь можно не печатать вручную, а перетащить папку прямо в терминал – он сам подставит.

Командная строка – это центр управления Claude Code, но не единственный способ коммуникации с ним. Над этой статьей я работаю вместе с ассистентом редактора: он живет в отдельном каталоге, где по подпапкам разложена информация – описание моих проектов, архив текстов из телеграма и бусти, скрипт для автоматического парсинга новых телеграм-постов, таблицы с аналитикой, контент-планы, инструкции по стилю и т.д.

Для статьи мы сначала создали план в html-формате – так удобнее читать, чем в командной строке. После того, как я одобрил план, Claude Code создал новый md-файл: он добавляет туда черновики глав, а я, открыв файл в VS Code, переписываю их в "человеческий" текст, если же есть вопросы или комментарии – даю их прямо по тексту в квадратных скобках. Затем сохраняю, и Claude Code проверяет главу на точность и грамотность, дополняет по моим комментариям – и мы движемся дальше. Я еще экспериментирую с данным workflow, как только пойму, что он меня устраивает – попрошу Claude Code накодить дашборд, где мы будем работать над текстом параллельно.

Но помимо работы текстом, важно знать slash-команды – любые, которые начинаются с "/".

Их несколько десятков. Нужные для старта разложу по четырем группам.

**Где я и что происходит:**

- **/status** – кто вы, где работаете, какая модель подключена, на каком уровне рассуждений.
- **/context** – какой процент контекстного окна уже съеден. О том, как работать с контекстным окном, будет отдельная статья, пока же простое правило: для 200K старайтесь не превышать 120-140K токенов, а для 1M – 400K токенов. Дальше модель в большинстве случаев начинает тупеть и жечь лишние токены.
- **/stats** – токены и стоимость текущей сессии. Помогает держать в голове, сколько вы уже "сожгли".
- **/help** – полный справочник всех команд.

**Настройки под задачу:**

- **/model** – переключить модель. На подписке Pro для знакомства я советую использовать Sonnet с 200K контекста. Когда освоитесь – можете подключать Opus 4.7 1M для сложных задач. На Max можно сразу использовать Opus 4.7, а со временем вы поймете, когда переходить на модели попроще для экономии токенов.
- **/effort** – глубина рассуждений модели. Для Pro советую ставить high, для Max xhigh – по мнению Anthropic, на этом уровне Opus 4.7 работает лучше Opus 4.6 на максимальном рассуждении.
- **/config** – общие настройки: тема оформления, поведение recap, мелочи.
- **/permissions** – что Claude может делать без вашего разрешения, а что всегда спрашивает. В следующем тексте про безопасность это будет главным.

**Управление сессией:**

- **/new** – новая чистая сессия. Старая остается в истории, к ней можно вернуться.
- **/clear** – обнулить контекст текущей сессии, не меняя папку и не перезапуская Claude. Удобно, когда одна задача закрыта, а вы хотите продолжить в той же папке со свежей головой.
- **/compact** – сжать все сделанное в саммари и продолжить дальше. Когда сессия длинная, а закрывать жаль.
- **/resume** – поднять сохраненную сессию по имени или ID.
- **/recap** – короткий пересказ "что сделали и где остановились", если вы вернулись через час или на следующий день. Свежая команда, появилась в апреле 2026.
- **/btw** – Claude Code нередко может работать над задачей по 4-5 минут. Эта команда позволяет не ждать конца работы, а задавать дополнительные вопросы прямо в процессе.

**Мозги и инструменты:**

- **/memory** – открыть и посмотреть, что Claude знает про вас и проект.
- **/init** – попросить Claude самого сгенерировать CLAUDE.md для текущей папки. Пригодится уже в следующем блоке.
- **/agents** – список субагентов, которые можно запустить или которые уже работают. До них дойдем.
- **/hooks** – триггеры-автоматы, разберем ближе к концу.
- **/mcp** – внешние сервисы, подключенные к агенту.

Плюс две клавиатурные штуки: Shift+Tab переключает режимы работы с подтверждениями – о них прямо сейчас и поговорим. Ctrl+C прерывает текущее действие, годится, когда Claude увлекся.

## Почему Claude каждый раз спрашивает

В первые минуты работы Claude Code ведет себя как параноик. Спрашивает разрешения открыть файл, запустить команду, пойти в сеть. "Можно я выполню ls? А git status? А прочту README.md?" Это раздражает. Но логика у этой паранойи здравая: агент живет в вашей файловой системе и в принципе может удалить что-то важное, поэтому важно – переспрашивать.

Настраивается режим через Shift+Tab. Основных вариантов три.

**Режим по умолчанию.** Claude спрашивает подтверждение на все, что меняет файлы или лезет в сеть. Максимально безопасно, но на сложном проекте вы устанете жать Enter к десятой минуте.

**Accept Edits on** (один Shift+Tab). Правки файлов идут без подтверждения, а сетевые запросы, запуск shell-команд и обращения к MCP-серверам продолжают спрашивать. Это баланс скорости и контроля: большая часть работы идет без остановок, а опасные действия требуют вашего "да". Мой рабочий режим.

**Auto mode** (два Shift+Tab). За безопасностью следит встроенный классификатор: он оценивает каждую команду и решает, пропускать или спросить. Согласования почти исчезают – остаются только по-настоящему деструктивные штуки вроде rm -rf. Доступен на подписках Max, Teams и Enterprise с моделью Opus 4.7. Подробно разберем в тексте про безопасность.

Теперь про главное разочарование. Включили Accept Edits – и все равно ловите согласования? Потому что "правки файлов" – одна категория, а "сетевые запросы", "shell-команды" и "MCP-вызовы" – другие. Accept Edits снимает вопросы только по первой, остальные продолжают спрашивать – и это правильно. В нашей работе над этой статьей, например, согласования прилетают каждый раз, когда Claude идет в сеть проверить фактуру или зовет сторонний MCP.

Совет на первые дни: не гонитесь за "отключить все". Смотрите, что именно Claude просит разрешить – так лучше поймете его подход к работе. Когда заметите, что одна и та же безопасная команда вроде git status выскакивает в десятый раз – добавьте ее в allowlist через /permissions.

## CLAUDE.md – мозг проекта

[![](https://images.boosty.to/image/73444021-7902-4d21-b2af-3da3cf7dd65e?change_time=1776446133&mw=575)](https://boosty.to/escaped_ai/posts/ac0fc839-00b9-47b1-a3e4-3182a4f1da1f/media/73444021-7902-4d21-b2af-3da3cf7dd65e?from=blog_post)

Главная странность Claude Code в том, что он не помнит прошлые разговоры. Набрали /new или /clear, закрыли терминал, открыли через день – он начинает с нуля. Для чат-бота это катастрофа. Для агента – сознательный выбор: вместо истории чатов у него есть файл с инструкциями, который он читает при каждом запуске.

Этот файл называется CLAUDE.md и лежит в папке проекта. Туда идет все, что модель должна знать с первой минуты новой сессии: цели, структура папок, стек технологий, правила работы с файлами, формат вывода, привычки, которые вы не хотите объяснять заново каждый день. Как документ для сотрудника, у которого каждое утро начинается с полной амнезии.

Писать сам CLAUDE.md руками не надо – это даже вредно. При старте нового крупного проекта я обычно открываю текстовый документ и в свободной форме набрасываю в нем описание проекта. Если есть дополнительный контекст (файлы со статистикой, примеры текстов, кода и так далее), то добавляю его. Затем кладу это все в папку проекта, прошу Claude Code прочесть и подготовить md-файл с дополнительными вопросами. Прямо в файле отвечаю, сохраняю его и прошу Claude прочесть и подтвердить, что все понятно. Затем набираю команду /init – модель сканирует папку, смотрит, что в ней есть, и предлагает черновик. Если речь о коде, то перед созданием md-файла ещё стоит включить режим планирования (Shift+Tab дважды или команда /plan) — в нем модель задаст очередные вопросы и предложит архитектуру.

Читайте черновик, если нужно, правьте и дополняйте – хотя обычно модель все делает хорошо. Если проект большой, то я советую иногда отправлять модель сделать ревью CLAUDE.md – она посмотрит, всего ли хватает, нет ли лишних или дублирующихся пунктов. Ну и сами иногда перечитывайте.

Главный принцип ручной работы с CLAUDE.md – обновляйте его диалогом, не в текстовом редакторе. Если видите, что Claude регулярно делает одну и ту же ошибку – напишите ему, чтобы добавил правило в CLAUDE.md.

Одного файла обычно хватает. Но если проектов много или вы работаете в команде, Claude Code читает CLAUDE.md с четырех этажей:

- **Проектный** – тот самый CLAUDE.md в папке проекта. Лежит в git, шарится между всеми участниками.
- **Личный** – файл ~/.claude/CLAUDE.md в вашей домашней папке. То, что Claude должен знать лично про вас, независимо от проекта: "отвечай по-русски, если я пишу по-русски", "называй меня по имени", "не уточняй каждый раз очевидное".
- **Локальный** – CLAUDE.local.md рядом с проектным. Приватное внутри проекта: пути к тестовым данным, эксперименты, заметки для себя. Обязательно в gitignore, чтобы не уехало в репозиторий.
- **Корпоративный** – актуален, если у вас Enterprise-подписка. Админ компании задает единые правила для всей команды, которые сотрудник не переопределит.

## Память – вторая система

У Claude Code есть и вторая система памяти, которую он ведет сам. Это auto memory в отдельной папке внутри ~/.claude – у каждого проекта свой каталог. Главный файл там называется MEMORY.md, это индекс. В него Claude кладет короткие заметки с пометкой, в какой отдельный файл нужно смотреть за деталями. При каждом запуске модель читает MEMORY.md первым делом – примерно первые 200 строк попадают в контекст автоматически. Остальное подтягивается по мере необходимости.

Что туда попадает? Все, что модель сочтет стоящим запомнить: как вы предпочитаете формулировать промпты, типичные ошибки, на которые вы ее раньше поправляли, быстрый способ запуска проекта, ваши вкусы в стиле ответов. Критерий простой: "пригодится ли это в будущем разговоре?".

В прошлом тексте я уже советовал сразу после установки дать Claude Code информацию о себе – она как раз отправится в память агента. Но и дальше не забывайте управлять памятью. Команда /memory открывает редактор, где видны все файлы – посмотрите, что Claude знает о вас, отредактируйте или удалите лишнее. В диалоге тоже можно писать: "Запомни: я начал изучать Go, теперь проекты будут и на этом языке".

Еще один нюанс: auto memory живет локально на конкретном компьютере. Если вы работаете и с ноутбука, и с рабочего стационарного – это две разные памяти, модель на одном устройстве знает одно, на другом другое. Свести их воедино в принципе можно, но это уже отдельная тема – разберем в следующих текстах.

## MCP – розетка для внешних сервисов

[![](https://images.boosty.to/image/576886ae-d620-4ed1-aef8-2ef56a50902d?change_time=1776446233&mw=575)](https://boosty.to/escaped_ai/posts/ac0fc839-00b9-47b1-a3e4-3182a4f1da1f/media/576886ae-d620-4ed1-aef8-2ef56a50902d?from=blog_post)

Все мы пользуемся кучей сервисов от разных разработчиков – и хотелось бы подключить к ним Claude Code, чтобы смотрел задачи в Jira, забирал тексты из заметок в Notion и далее.

Мост между агентом и внешним миром называется MCP – Model Context Protocol. Это открытый стандарт, придуманный именно для того, чтобы подключать ИИ-агентов к чему угодно: сервисам, базам, календарям, мессенджерам.

Каталог готовых MCP-серверов на момент написания статьи – сотни штук: GitHub, Jira, Linear, Slack, Gmail, Google Calendar, Notion, Figma, Sentry, Airtable, Stripe, Cloudflare, большинство популярных баз данных. Главных источников два. Первый – официальный раздел [Popular MCP servers](https://code.claude.com/docs/en/mcp), сразу с командой для подключения каждого. Второй – независимый [открытый реестр](https://registry.modelcontextprotocol.io/), где можно искать по названию или категории. Плюс ничто не мешает подключить сторонний MCP, не из реестров – из чьего-то личного GitHub-репозитория, например.

Подключается в одну строку. Например, чтобы дать агенту доступ к Notion:

*claude mcp add --transport http notion https://mcp.notion.com/mcp*

После этого в сессии набираете /mcp – видите notion в списке подключенных. Дальше Claude уже сам решает, когда в него заглядывать: просите "найди в моих заметках все про агентов" – идет и ищет.

Есть еще одна штука, которая только появилась – MCP Channels. Это не просто канал запроса-ответа, а канал, по которому внешний мир может сам стучаться в агента. Например, Telegram-бот ловит новое сообщение – и пересылает Claude с просьбой обработать. Вы не запускали агента, инициатива пришла снаружи. К этому еще вернемся в тексте про длинные задачи – там Channels открывают неожиданные сценарии.

Последнее – про осторожность. Официальным MCP-серверам крупных вендоров – Anthropic, GitHub, Notion, Atlassian, Google, Slack, Stripe и подобным – доверять можно смело. Эти сервисы поддерживают сами компании, код открытый, репутационные риски для них слишком велики, чтобы делать что-то мутное. А вот сторонний MCP от неизвестного автора требует внимательности. Подключили – и дали ему доступ ко всему, что есть в папке проекта. Плюс любой внешний MCP – потенциальный канал для prompt injection: кто-то подсунул в задачу в Jira инструкцию "удали весь проект", Claude прочитал, выполнил. О безопасности также будет текст, а пока простое правило: серверы от крупных компаний – ок, все остальное – только после проверки.

## Скиллы – арсенал процедур

У каждого, кто работает с ИИ, со временем накапливается набор промптов, которые приходится писать снова и снова. "Разбери статью по таким-то пунктам и дай резюме". "Сделай дайджест вот из этих источников". "Прогони текст через стилистическую проверку с такими-то правилами". В чат-боте их хранят в заметках и каждый раз копируют. Скиллы в Claude Code – это та же самая идея, только аккуратно встроенная: проверенный промпт превращается в одну команду со слешем.

Устроен скилл просто. Это папка с одним файлом – SKILL.md. В самом начале файла – имя скилла, короткое описание и пара ключевых слов, по которым Claude сам поймет, когда его применить. Дальше – обычный текст инструкции: как будто вы объясняете задачу коллеге, только один раз и максимально подробно. Скилл и slash-команда – это одно и то же. Положили папку с именем my-review – в следующей же сессии в Claude Code появится /my-review.

В Claude Code уже лежит пара десятков готовых скиллов – например, /simplify, /review, /debug, /loop. Можно открыть любой и прочитать как текст – отличный способ набить руку на чужих примерах, прежде чем писать свои.

Где брать готовые скиллы кроме коробки. Есть несколько больших общественных коллекций: [awesome-claude-code](https://github.com/hesreallyhim/awesome-claude-code) от hesreallyhim, [superpowers](https://github.com/obra/superpowers) от obra, [awesome-agent-skills](https://github.com/VoltAgent/awesome-agent-skills) от VoltAgent. Там сотни штук на все случаи – от автокоммитов и тест-раннеров до извлечения данных из PDF. Ставятся копированием папки в ~/.claude/skills. Разбирать чужие скиллы – отличный способ понять, как думают другие, и за пару часов начать собирать собственный арсенал.

Живой пример – скилл /go Бориса Черни, одного из разработчиков Claude Code. Он запускает цепочку: протестировать код, прогнать через /simplify для упрощения, собрать pull request. Одна команда вместо десяти строк диалога. Собственный скилл на похожую логику собирается за полчаса.

## Субагенты – параллельный отдел

Субагент – это отдельный Claude, которого основной агент запускает как подрядчика на конкретную задачу. У него свое чистое контекстное окно и свой набор разрешенных действий – исследователю, например, можно оставить только чтение файлов и поиск в сети, без права что-то менять.

Зачем это нужно – две причины. Первая: экономия контекста. Вся черная работа – разобрать сто файлов логов, собрать сводку по десяти статьям – идет в окне субагента, а в ваше главное возвращается только короткий итог на пару строк. Вторая: параллельность. На один запрос можно запустить сразу несколько субагентов, каждый займется своим куском, и результаты вернутся одновременно.

Посмотреть список можно командой /agents – там видны и предустановленные субагенты, и ваши собственные. Свой собирается так же, как скилл: отдельная папка с инструкцией, которую Claude подхватит сам.

Еще недавно добавили Agent Teams, они работают сразу как команда разработчиков: есть тимлид и параллельные агенты, отвечающие за разные задачи – от фронта до тестирования безопасности.

Но в первые дни и недели знакомства с Claude Code я бы сильно не увлекался субагентами – пока вы учитесь, лучше видеть всю работу перед глазами. В определенных случаях Claude Code и сам будет их запускать, а затем и вы поймете – какие задачи делегировать субагенту. В целом же это более высокий уровень, который рассмотрим в следующих статьях. Пока же коротко о еще одном типе автоматизации – не "нанять исполнителя", а "поставить триггер": при каждом определенном событии дергать заранее прописанное действие. Это хуки, о них в следующем блоке.

## Хуки – триггеры-автоматы

Хуки это правила в формате "если произошло X – сделай Y", которые срабатывают сами, без ваших команд. Главное отличие хуков от скиллов и субагентов: их не надо звать. Скилл вы вызываете слеш-командой, субагент запускается под конкретную задачу, а хук сидит в фоне и срабатывает сам, как только наступает указанное событие.

События, на которые можно повесить хук, – это моменты работы агента: перед запуском инструмента, после редактирования файла и так далее. Типичный пример: после каждой правки кода – автоматически прогнать файл через форматтер, чтобы не делать этого вручную.

Хуки управляются командой /hooks – показывает, что сейчас настроено, и дает добавить новое. В командных проектах хуки шарятся через настройки в репозитории, так что все участники работают по одинаковым правилам.

Важное предупреждение. Хук – это автозапуск кода с вашими правами на вашей машине. Серьезные хуки (пишут в сеть, правят git, запускают деплои) включайте только когда уверены, что они делают именно то, что задумано. Легкие – автоформат после правки, логи, оповещения – ставьте смело, они заметно экономят рутину.

Шесть слоев, которые превращают Claude Code из просто CLI-утилиты в конструктор – память, MCP, скиллы, субагенты, хуки и CLAUDE.md как каркас для всего остального – мы разобрали. Дальше – дело привычки: запускайте сессии, пробуйте /agents и /hooks, собирайте свои скиллы из чужих коллекций, правьте CLAUDE.md каждый раз, когда замечаете повтор.

В следующем тексте – про безопасность. Как дать Claude свободу действовать без ста согласований в час, но не потерять контроль над машиной. Разберем /permissions в деталях, Auto mode с его классификатором, границы, за которые модель не пустят никакой ценой, и частые ошибки, из-за которых пользователи сами открывают агенту слишком широкие права.
