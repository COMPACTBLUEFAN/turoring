# /session — выдать сессию

1. Порядок старта — `AGENTS.md`, раздел 2: `ПРОГРЕСС.md` → трекер → `НЕДЕЛЯ.md` текущей недели → последний файл сессии → `ЗАМЕТКИ.md`.
2. Есть сданная, но не проверенная сессия — сначала проверь её (как в /check), потом выдавай.
3. Действуй по сценарию A2. Нет `НЕДЕЛЯ.md` текущей недели — сначала сценарий A.
4. Аргумент:
   - код занятия — выдай его, если это не ломает зависимости из `РАСПИСАНИЕ.md` (иначе скажи, что сначала нужно);
   - «интерес» — выдай или покажи занятия интересов недели (правило 27); выбор конкретного интереса вне очереди — через /interest;
   - «ивент» — выдай ивент интересов на выходные (правило 29) и запиши его в журнал ивентов трекера.
4a. **Если автозапуски выключены** — сделай и то, что автозапуск сделал бы на сегодня по сценарию H: в четверг — второй интерес, в пятницу — ивент интересов, в воскресенье — тест недели. План новой недели в понедельник — через /week.
5. Пользователь сам просит ещё одну сессию — лимит «одна открытая основная» не действует.
6. Перечитай файлы перед правкой и проверь после записи (пользователь мог править его в Obsidian).
7. Ответ — 2–3 строки: тема, примерное время, ссылка на файл.
