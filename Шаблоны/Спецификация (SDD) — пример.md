# 📋 Спецификация: Чтение одной заметки по относительному пути через CLI

> Шаблон SDD (Spec-Driven Development). Пишется **до кода**.
> Дата: 30.10.2026 · Статус: утверждена · Проект: полигон «Второй мозг» (second-brain) · Ветка: `spec/cli-read-note`

## 🎯 Цель

CLI-утилита принимает относительный путь к заметке внутри хранилища Obsidian, проверяет безопасность пути и выводит полное содержимое `.md` файла в stdout в кодировке UTF-8 за время < 100 мс, либо возвращает код возврата 1 и понятное сообщение в stderr при некорректном вводе.

---

## 📦 Контекст

- **Зачем:** Ходячий скелет полигона (Задача 1 из дерева декомпозиции). Обеспечивает базовую сквозную проверку цепочки: запуск CLI-процесса → чтение настроек корня vault → безопасная валидация пути → доступ к файлу на диске → вывод в stdout.
- **Что уже есть и не трогаем:** Пустой репозиторий с файлом правил `AGENTS.md`. Файлы реального хранилища пользователя не трогаем никогда (Strict Read-Only).
- **Стек и версии:** Python 3.10+, стандартная библиотека (`pathlib`, `sys`, `argparse`), `pytest`, `hypothesis`.
- **Файлы, которые нужны агенту для контекста:**
  - `AGENTS.md` в корне репозитория 
- **Архитектурное решение:**
  - Логика проверки пути и чтения файла изолирована в модуле ядра `src/reader.py`.
  - Модуль `src/cli.py` является тонкой обёрткой над ядром (парсит аргументы CLI и перехватывает ошибки ядра для формирования exit code и stderr).
  - Это гарантирует, что на Неделе 8 те же самые функции ядра станут инструментами FastMCP без модификации логики чтения.

---

## ➡️ Вход

1. **Конфигурация окружения:**
   - Переменная окружения `OBSIDIAN_VAULT_PATH`: строковый путь к каталогу хранилища заметок на диске. Директория обязана существовать на диске.
   - Любые аргументы командной строки для переопределения пути к хранилищу (вроде `--vault`) принципиально запрещены во избежание атак с подменой корня.
2. **Аргумент команды CLI:**
   - Позиционный аргумент: относительный путь к файлу заметки относительно корня хранилища (тип: строка, например: `inbox/idea.md`, `Projects/task.md`, `README.md`).
3. **Ограничения на входные данные:**
   - Разрешены только файлы с расширением `.md` (регистронезависимо: `.md`, `.MD`).
   - Запрещены любые пути, выходящие за пределы корня vault через `..` или абсолютные пути диска (`C:\...`, `/...`).
   - Запрещён доступ к служебным конфигурационным каталогам (любая папка в пути, начинающаяся с точки: `.obsidian`, `.git`, `.trash`, `.cache` и т.д.).
   - Максимальный размер файла заметки — **не более 10 МБ** (защита от исчерпания памяти и DoS при передаче нетипично больших файлов).

---

## ⬅️ Выход

1. **При успешном чтении:**
   - Код возврата процесса (Exit code): `0`.
   - Поток `stdout`: сырой текст заметки в кодировке UTF-8 без модификаций и без подмены переносов строк (сохраняется оригинальный CRLF или LF).
   - Поток `stderr`: пустой.
2. **При ошибке:**
   - Код возврата процесса (Exit code): `1`.
   - Поток `stdout`: пустой.
   - Поток `stderr`: лаконичное сообщение об ошибке на русском языке (без утечки абсолютных путей файловой системы хоста).

## ⚠️ Ошибки и поведение системы

| Ситуация | Реакция ядра (`src/reader.py`) | Реакция CLI (`src/cli.py`) | Сообщение в stderr |
|---|---|---|---|
| Не задана переменная `OBSIDIAN_VAULT_PATH` | `ConfigurationError` | Exit code 1 | `Ошибка конфигурации: переменная окружения OBSIDIAN_VAULT_PATH не задана` |
| Указанный путь хранилища не существует или не папка | `ConfigurationError` | Exit code 1 | `Ошибка: директория хранилища не существует` |
| Попытка выхода за пределы vault (`..`, абсолютный путь) | `SecurityError` (наследник `ValueError`) | Exit code 1 | `Ошибка безопасности: запрошенный путь выходит за пределы хранилища` |
| Запрос к служебным каталогам (начинающимся с `.` в имени) | `SecurityError` (наследник `ValueError`) | Exit code 1 | `Ошибка безопасности: доступ к системным каталогам запрещён` |
| Расширение файла не `.md` (`.png`, `.json`, `.exe`) | `ValidationError` (наследник `ValueError`) | Exit code 1 | `Ошибка: поддерживаются только заметки с расширением .md` |
| Размер заметки превышает 10 МБ | `PayloadTooLargeError` (наследник `ValueError`) | Exit code 1 | `Ошибка: размер файла заметки превышает лимит 10 МБ` |
| Файл не существует внутри хранилища | `FileNotFoundError` | Exit code 1 | `Ошибка: заметка не найдена` |
| Указанный путь является директорией, а не файлом | `IsADirectoryError` | Exit code 1 | `Ошибка: указанный путь является директорией, а не файлом` |
| Ошибка декодирования UTF-8 | `UnicodeDecodeError` | Exit code 1 | `Ошибка: файл не является корректным текстом UTF-8` |

## ✅ Критерии приёмки

- [ ] 1. **Сквозное чтение:** Вызов CLI с валидным относительным путем возвращает код `0` и выводит содержимое файла в `stdout`.
- [ ] 2. **Производительность:** Время выполнения вызова CLI на чтение файла размером до 1 МБ не превышает **100 мс**.
- [ ] 3. **Память:** Потребление оперативной памяти процесса не превышает **50 МБ**.
- [ ] 4. **Инвариант Path Traversal:** Любая попытка чтения файла вне корня хранилища (через `..`, абсолютный путь или симлинк наружу) пресекается, код возврата `1`, прочитано **0 байт** данных извне vault.
- [ ] 5. **Инвариант защиты секретов и конфигов:** Попытка чтения любых файлов внутри `.obsidian/`, `.git/` и `.*name*` подобных директорий пресекается, код возврата `1`, прочитано **0 байт**.
- [ ] 6. **Инвариант типа данных:** Попытка чтения не-markdown файлов (`.txt`, `.pdf`, `.json`, `.env`) пресекается, код возврата `1`.
- [ ] 7. **Разделение архитектурных слоёв:** Модуль `src/cli.py` содержит не более **40 строк кода** и не выполняет работу с диском напрямую, делегируя чтение функциям `src/reader.py`.
- [ ] 8. **Запрет на системный шелл:** В коде отсутствуют вызовы `subprocess(shell=True)` и функции `os.system`.
- [ ] 9. **Синтетические тесты:** Юнит- и интеграционные тесты используют только временные каталоги `tmp_path` и фикстуры, не обращаясь к реальному Obsidian хранилищу пользователя.
- [ ] 10. **Лимит размера заметок:** Попытка чтения файла размером более **10 МБ** пресекается до вычитки в память с кодом возврата `1` и ошибкой размера.

## 🚫 Ограничения и не-цели

- **Строго Read-Only:** В репозитории принципиально не создаются функции модификации, дозаписи (`append`) или удаления заметок.
- **Не-цели задачи 1:**
  - Настраиваемый чёрный список произвольных папок пользователя (например, запрет чтения папок `private/` или `archive/`): **не входит в Задачу 1**. В первой задаче структурно блокируются все скрытые каталоги (`.*`). Конфигурируемый чёрный список через файл настроек или `.vaultignore` выносится в отдельную задачу расширения безопасности, чтобы не раздувать ходячий скелет парсингом конфигов.
  - Поиск по заметкам и подстрокам (это Задача 2).
  - Извлечение и парсинг тегов `#тег` (это Задача 3).
  - Полнотекстовый поиск (это Задача 4).
  - Парсинг markdown-структуры, ссылок `[[...]]` и frontmatter (это Задачи 5 и следующие).
  - Реализация интерфейса FastMCP / протокола MCP (это Задача 6 / Неделя 8).
  - Поддержка произвольных текстовых форматов кроме `.md`.

## 🛡 Безопасность

1. **Валидация путей (Path Traversal):**
   - Используется `pathlib.Path.resolve()`.
   - Проверка вхождения в корень: `resolved_target.is_relative_to(resolved_vault)`.
   - Запрещено использовать `assert` для валидации входных путей — строго проверки через `if not ...: raise SecurityError(...)` (защита от отключения при оптимизации Python `python -O`).
2. **Изоляция секретов:**
   - Пути к системным папкам `.git` и `.obsidian` проверяются по частям пути (`target_path.parts`), блокируя любой уровень вложенности.
3. **Сообщения об ошибках:**
   - В сообщения `stderr` запрещено подставлять полный абсолютный путь хоста (`C:\Users\...`), чтобы не раскрывать структуру каталогов окружения при атаках.

## 🧪 Тест-кейсы (Red)

### 🔬 Тесты-свойства (Hypothesis)

Помимо фиксированных кейсов из таблицы ниже, для функций валидации и чтения ядра (`src/reader.py`) **обязательны property-based тесты** через библиотеку `Hypothesis` (не менее 100 итераций на каждое свойство):

1. **Инвариант безопасности путей (Path Traversal):**
   - *Стратегия:* `st.text()` — генерация любых произвольных строковых путей (слеши в обе стороны, двоеточия, переходы `..`, спецсимволы, юникод, пробелы).
   - *Свойство:* Функция валидации пути обязана для любого входа либо вернуть канонический `Path`, для которого строго истинно `path.is_relative_to(vault_root.resolve())`, либо выбросить `SecurityError` / `ValidationError`. Функция **ни при каком вводе** не имеет права вернуть путь за пределами хранилища.
2. **Инвариант расширений файлов:**
   - *Стратегия:* `st.text()` в качестве имени файла + случайные сгенерированные расширения из `st.text()`.
   - *Свойство:* Если расширение файла без учёта регистра не равно `.md`, функция обязана гарантированно завершаться ошибкой `ValidationError`.
3. **Инвариант скрытых и служебных каталогов:**
   - *Стратегия:* генерация путей, где хотя бы один из сегментов пути начинается с точки (`st.from_regex(r'^\..+')`).
   - *Свойство:* обращение к любому файлу внутри скрытой папки обязано гарантированно блокироваться с ошибкой `SecurityError`.

## ❓ Открытые вопросы

- [x] **Вопрос 1:** Что делать, если внутри хранилища создан симлинк, указывающий на файл вне vault?
  - *Решение:* Метод `resolve()` разворачивает симлинки до физического пути. Если физический путь выходит за пределы `vault_root.resolve()`, `is_relative_to` возвращает `False` и выбрасывается `SecurityError`.
- [x] **Вопрос 2:** Как передавать путь к vault в автоматических тестах?
  - *Решение:* Через фикстуру `monkeypatch.setenv("OBSIDIAN_VAULT_PATH", str(tmp_path))` в `conftest.py`.
